# Leakage-aware evaluation of ransomware address detection on BitcoinHeist

Code, model configuration, split definitions, result files, and figure/table scripts for the paper

> A. I. Fajri, M. I. Irawan, and F. Mahananto, "Leakage-Aware Evaluation of Ransomware Address Detection on the
> BitcoinHeist Dataset: Address-Disjoint, Temporal, and Zero-Day Benchmarks," submitted to *JOIV: International
> Journal on Informatics Visualization*.

The paper audits the BitcoinHeist dataset for two leakage channels (address overlap and a calendar shortcut) and
compares five classifiers under six evaluation protocols. Everything in the paper can be regenerated from the raw
CSV file with the scripts in `src/`.

## Repository layout

| Path | Content |
|---|---|
| `src/01_main_experiments.py` | Dataset audit; random, address-disjoint, and temporal protocols for five classifiers and three feature sets (seeds 0-2); family attribution |
| `src/02_rolling_weighting.py` | Rolling-origin evaluation (three seeds) and XGBoost with class weighting |
| `src/03_revision_experiments.py` | Withheld-family protocol with validation-calibrated thresholds; combined temporal + address-disjoint + emerging-family protocol; paired address-purge experiment; cluster bootstrap; seeds 3-4 of the main experiment |
| `src/04_overlap_isolation.py` | Paired leak-injection experiment on the address-disjoint split and decomposition of the address-purge effect by seen and unseen addresses |
| `src/make_splits.py` | Regenerates the train / validation / test record indices of every protocol and their SHA-256 checksums |
| `src/make_tables_figures.py`, `src/msstats.py` | Regenerate Tables V-XI, Figs. 1-5, and every statistic quoted in the text from the result files |
| `config/models.json` | Complete model, preprocessing, seed, calibration, and bootstrap configuration |
| `splits/manifest.csv` | Size, number of ransomware records, and SHA-256 checksum of every index array |
| `results/` | Result files produced by the three experiment scripts (inputs of the tables and figures) |
| `figures/` | `f1.png` ... `f5.png` (Figs. 1-5) and `tables.md` as generated by `make_tables_figures.py` |

## Data

The dataset is not redistributed here. Download `BitcoinHeistData.csv` from the UCI Machine Learning Repository
(dataset 526, https://doi.org/10.24432/C5BG8V, CC BY 4.0). The file used in the paper was retrieved on
10 November 2026 and has 2,916,697 records, no missing values, and no fully duplicated records. It is used as
distributed: no imputation, no outlier removal, no resampling.

## Reproducing the paper

```bash
DATA=/path/to/BitcoinHeistData.csv

# 1. Experiments (about 3.5 hours in total on a two-core CPU with 8 GB RAM; no GPU needed)
python src/01_main_experiments.py     $DATA results
python src/02_rolling_weighting.py    $DATA results
python src/03_revision_experiments.py $DATA results
python src/04_overlap_isolation.py    $DATA results

# 2. Tables, figures, and statistics
python src/make_tables_figures.py results figures

# 3. Optional: regenerate and verify the split indices
python src/make_splits.py $DATA splits_check          # add --save to store the index arrays as .npz
diff <(cut -d, -f1,2,5 splits/manifest.csv) <(cut -d, -f1,2,5 splits_check/manifest.csv) && echo "splits identical"
```

`03_revision_experiments.py` accepts an optional third argument to run selected stages, for example
`E5,E6` (stages: `E5` withheld family, `E6` combined protocol, `E2` address purge and bootstrap, `E4` bootstrap
for the temporal protocols, `E1` additional seeds; run `E2` and `E4` together).

## Evaluation protocols

| Protocol | Training partition | Test partition |
|---|---|---|
| Random | Stratified 70% of the records | Remaining 30% |
| Address-disjoint | All records of 70% of the addresses | All records of the other addresses |
| Temporal | Years 2011-2015 | Years 2016-2018 |
| Rolling origin | Years up to N | Year N + 1, N = 2011, ..., 2016 |
| Withheld family | Address-disjoint training partition without family k | Family k and white records of the address-disjoint test partition |
| Combined | Years up to N | Year N + 1, addresses unseen in training; positives divided into emerging and continuing families |

Two paired experiments isolate the effect of address overlap on identical test records: *leak injection* (half of
the records of every repeated test address of an address-disjoint split are moved into training) and *address
purge* (training records whose address occurs in the test partition of a random split are deleted).

Decision thresholds of the withheld-family and combined protocols are calibrated on a validation part (20% of the
training addresses) to a 1% false-positive rate and then applied unchanged to the test partition.
